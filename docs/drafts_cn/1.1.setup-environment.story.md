## 开发备注

### 项目结构模式
[来源: 当前packages目录结构]
项目使用pnpm工作空间，包位于`packages/`目录下。每个包遵循以下结构：
```
packages/
├── [package-name]/
│   ├── src/
│   │   └── index.ts
│   ├── package.json
│   ├── tsconfig.json
│   └── README.md
```

### 包命名约定
[来源: package.json分析]
所有包都使用`@prompt-optimizer/`命名空间（不是PRD中提到的@prompt-manager）。新包应该是：
- `@prompt-optimizer/webdav`
- `@prompt-optimizer/editor`

### 构建系统配置
[来源: 根package.json]
项目使用：
- pnpm作为包管理器（版本10.6.1）
- npm-run-all用于构建编排
- Vite用于打包（如适用）
- 构建脚本遵循模式：根package.json中的`build:[package]`

### TypeScript配置
[来源: 现有tsconfig.json文件]
所有包都扩展基础配置：
- TypeScript 5.8.2
- 启用严格模式
- 为每种包类型适当设置模块解析

### 开发脚本模式
[来源: 根package.json脚本]
```json
"build:webdav": "pnpm -F @prompt-optimizer/webdav build",
"build:editor": "pnpm -F @prompt-optimizer/editor build"
```
如果可以并行构建，这些应该添加到build:parallel脚本中。

### Docker配置位置
Docker文件应放在项目根目录，遵循通用约定。docker-compose.dev.yml应与package.json并列。

### 测试
[来源: 现有测试配置]
- 测试使用Vitest框架
- 测试文件位于每个包内的tests/目录中
- 从根目录或包目录运行`pnpm test`
- 测试配置在vitest.config.js或vitest.config.ts中

### 重要集成点
- 现有包包括：core、ui、web、extension、desktop、mcp-server
- 构建顺序很重要：core和ui必须在web之前构建
- 开发模式使用带监听器的并发构建
- 项目支持多个部署目标（web、extension、desktop）
