## Dev Notes

### Project Structure Pattern
[Source: Current packages directory structure]
The project uses pnpm workspaces with packages under `packages/` directory. Each package follows this structure:
```
packages/
├── [package-name]/
│   ├── src/
│   │   └── index.ts
│   ├── package.json
│   ├── tsconfig.json
│   └── README.md
```

### Package Naming Convention
[Source: package.json analysis]
All packages use the `@prompt-optimizer/` namespace (not @prompt-manager as mentioned in PRD). New packages should be:
- `@prompt-optimizer/webdav`
- `@prompt-optimizer/editor`

### Build System Configuration
[Source: root package.json]
The project uses:
- pnpm as package manager (version 10.6.1)
- npm-run-all for build orchestration
- Vite for bundling (where applicable)
- Build scripts follow pattern: `build:[package]` in root package.json

### TypeScript Configuration
[Source: existing tsconfig.json files]
All packages extend from a base configuration with:
- TypeScript 5.8.2
- Strict mode enabled
- Module resolution set appropriately for each package type

### Development Scripts Pattern
[Source: root package.json scripts]
```json
"build:webdav": "pnpm -F @prompt-optimizer/webdav build",
"build:editor": "pnpm -F @prompt-optimizer/editor build"
```
These should be added to the build:parallel script if they can be built in parallel.

### Docker Configuration Location
Docker files should be placed in project root, following common convention. The docker-compose.dev.yml should be alongside package.json.

### Testing
[Source: existing test configuration]
- Tests use Vitest framework
- Test files located in tests/ directory within each package
- Run with `pnpm test` from root or package directory
- Test configuration in vitest.config.js or vitest.config.ts

### Important Integration Points
- The existing packages include: core, ui, web, extension, desktop, mcp-server
- The build order matters: core and ui must build before web
- Development mode uses concurrent builds with watchers
- The project supports multiple deployment targets (web, extension, desktop)
